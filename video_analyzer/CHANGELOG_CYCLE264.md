# Cycle 264 — four-table OCR benchmark adapter (synthetic validation)

## Scope and source

Read `docs/VIDEO_ANALYZER_SCOPE.md`. This is offline analysis of **recorded** PLO5/PLO6 sessions, not a playable simulator, real-time poker connector, or automatic poker recommendation. Existing `offline_four_table_ocr_proposals.py` emits `raw_ocr_text` with `parsed_candidate: null` and `needs_manual_review`, whereas the Cycle 263 evaluator expects normalized candidates. This adapter bridges those two contracts without modifying either original module.

## Implemented

- `offline_four_table_ocr_benchmark_bridge.py` consumes the exact report shape emitted by `offline_four_table_ocr_proposals.scan` and a separate human-label JSON array, then calls the existing `offline_recognition_benchmark_v2.evaluate`.
- Conservative exact parser: `pot` and `bet` accept plain decimal numbers only; `hero_cards` requires exactly five or six explicit card tokens; `board` accepts one to five explicit card tokens. Unparseable or ambiguous OCR text abstains instead of inventing facts.
- Preserves table IDs, source timestamps, source candidate indices, and SHA-256 fingerprints of the original OCR report and human labels. Rejects duplicate candidate identities, nonfinite timestamps, invalid sources, duplicate JSON keys, symlinks and output overwrites.
- `action` and `stack` are **not** silently scored; exclusions are counted explicitly because the Cycle 263 evaluator does not support them. The tool is a diagnostic only: `ready_for_equity_or_ev: false`, `hands_reconstructed: false`.

## Usage

```bash
python video_analyzer/offline_four_table_ocr_benchmark_bridge.py original_ocr_report.json manually_annotated_gold.json new_ocr_benchmark.json
```

Example gold file: `[ {"table_id": 1, "field": "pot", "timestamp": 1.0, "expected": 12.5} ]`. Cards are arrays such as `"expected": ["As", "Kh", "Qd"]`. Exact card order is significant in the evaluator. Gold labels are separate annotations and must be checked against the source video by a human.

## Not verified / blocked

- No authorized 3–5 minute labeled real video. No real OCR accuracy, calibrated confidence, actual hand reconstruction, full 40–60 minute session, Windows behavior or end-to-end FFmpeg/Tesseract run verified in this cycle.
- The adapter was exercised with synthetic reports matching the scanner schema, **not** with an actual report generated by Tesseract. Source recording SHA and crop SHA values are carried as unverified claims, not independently checked against video bytes by this adapter.
- Existing evaluator's temporal matching maximizes match count, not minimum timestamp error. Results cannot authorize equity or EV.
